# Тарифы 2.0 — снос COURSE + мультимесяц PLATFORM — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`).
> **⚠️ ДЕНЬГИ — ЭТОТ ПЛАН РЕАЛИЗУЕТСЯ ТОЛЬКО ПОСЛЕ ДИЗАЙН-РЕВЬЮ (owner-gate).** Секция «Design-review: решения и риски» ниже — читать ПЕРВОЙ. Ряд пунктов вскрыт грепом сверх спеки.

**Goal:** Снести мёртвый тариф COURSE (0 активных подписок) из пути покупки и витрины; добавить объёмные скидки PLATFORM за 3/6 мес (7990/13990) как отдельные `SubscriptionPlan`-строки по `intervalDays`; сохранить существующую биллинг-машину (полная сумма периода вперёд + рекуррент по цене периода) и акцию «2 месяца по цене одного» на 1-мес пути.

**Architecture:** Мультимесяц = отдельные PLATFORM-планы `intervalDays` 30/90/180 (Option A спеки). Матан суммы/периода уже читается живьём из `plan.intervalDays`/`plan.price` — новой биллинг-логики нет. **Реальная работа — не исполнение, а ВЫБОР плана:** резолв «единственного PLATFORM» (`findFirst({type:'PLATFORM'})`) ломается при 3 строках; контракт покупки меняется с `planType` на явный выбор периода (`intervalDays`), и все неявные «дай PLATFORM» пинуются к нужному плану. Плюс широкий copy-sweep COURSE/1990 и паритет `/billing`↔`/pricing` через общие компоненты `components/pricing/*`.

**Tech Stack:** Next.js 14, tRPC, Prisma (Supabase), CloudPayments (клиентский виджет + рекуррент), Zod, Tailwind. Миграция планов — аддитивный tsx через Supabase Mgmt API (строки-данные, схема НЕ меняется).
